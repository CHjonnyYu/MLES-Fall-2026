Integrate the final evidence contract

Integration means a reconstructable result

Connect input, source, code, configuration and output into one evidence chain.

Worked reasoning: Artifact identities; manifest; runner; environment; replay comparison; oral explanation.

What does a project screenshot omit?

Executable procedure, inputs, dependency versions, rejected cases and the basis of its claims.

Scope the final claim before packaging

State exactly what the synthetic workflow demonstrated and did not demonstrate.

Worked reasoning: The frozen local implementation matches these independent teaching fixtures; no physical deployment or live-model evaluation is established.

Why not say the agent is reliable?

That omits the task, tested cases, assumptions and scope. Use a claim that the exported evidence can actually support.

The manifest names required payloads

Hash input, protocol, configuration and source; exclude the manifest from hashing itself.

Worked reasoning: A file cannot generally include its own final hash. Keep the required payload hashes in a separate manifest.

Does a matching unsigned manifest authenticate a sender?

No. Someone can replace both payload and digest. Trust needs an external reference or signature.

Use canonical JSON deliberately

Sort keys and fixed serialization identify one representation, not all equivalent objects.

Worked reasoning: Whitespace changes a raw-file hash. Canonical hashing compares the declared serialized representation.

Which hash should the handover record use?

Declare whether it hashes exact files or canonical values. This package uses exact saved payload bytes for integrity.

Source is safer to inspect than opaque objects

A readable runner rebuilds the workflow from supplied files.

Worked reasoning: The package contains JSON and Python source, not serialized executable model objects.

Does readable source make execution safe?

No. Review it and use an appropriate environment. Arbitrary Python can still perform harmful operations.

A new process removes hidden globals

Run the saved source from a fresh working directory with explicit paths.

Worked reasoning: The runner must not require an in-memory variable, previous cell or current notebook directory.

What does a fresh process still share?

It can share interpreter, packages, operating system and hardware. It is not independent scientific replication.

Replay compares computations, not outcomes

A zero replay difference does not imply an accurate physical model.

Worked reasoning: Prediction error compares against observations; replay difference compares outputs of the same declared procedure.

Can an incorrect workflow replay perfectly?

Yes. Reproducibility preserves the computation, including its defects. Independent fixtures test correctness separately.

Align identities before values

Compare case IDs and output fields before applying numeric tolerance.

Worked reasoning: A comparison must join by stable IDs or require the declared sequence. Bare positional vectors can mismatch cases.

Does matching aggregate mean prove row alignment?

No. Permutations can preserve an aggregate while assigning values to the wrong cases.

Record the actual environment

Save Python, package versions, platform, source hash and invocation.

Worked reasoning: The replay runner is standard-library only; plotting stays in the notebook. Preserve both scopes.

Does a seed guarantee cross-version equality?

No. Algorithms, libraries and numeric implementations can change. Name the environment and comparison criterion.

Summary: package the claim with its limits

An honest handover includes failures, replay evidence and missing validation.

Worked reasoning: A different protocol, unit convention or population can invalidate the original conclusion.

What will the next hour test?

Extracted files, corrupted payloads, explicit failure messages and a complete five-minute explanation.

Replay, integrity checks, and oral defense

The ZIP must contain everything it promises

Use a required-file list rather than archiving arbitrary runtime state.

Worked reasoning: Read source and paths. The reference extraction rejects unexpected members and does not execute received code automatically.

Why avoid arbitrary runtime archives?

They may leak secrets, personal files or irrelevant state and make the intended procedure unclear.

Task 4: extract into a fresh directory

Verify manifest keys and bytes before starting the runner.

Worked reasoning: Removing protocol.json must fail before the analysis claims a protocol-based result.

What should a failed integrity check do?

Stop with a specific error. Do not retrain, repair or regenerate missing evidence silently.

Task 5: replay from saved files

Use an explicit interpreter, runner path, bundle root and output path.

Worked reasoning: A launched process is not completed execution. Check successful termination and parse its result file.

Why preserve stderr on failure?

It is evidence of the failing dependency or predicate. Replacing it with a success message destroys diagnosability.

Task 6: compare an aligned result vector

Use case IDs then the declared absolute-plus-relative tolerance.

Worked reasoning: This small runner should agree numerically in this environment. Report the actual maximum difference, not a promised zero.

What if a metric agrees but predictions differ?

Do not call it a successful replay. Aggregate agreement can conceal per-case differences.

Tamper detection is not authenticity

A changed copied payload should fail against the preserved manifest.

Worked reasoning: A harmless-looking blank line changes the exact-file hash even if a parser would ignore it.

What if both payload and manifest are replaced?

Unsigned consistency checks may pass. A trusted external reference or signature is needed for sender authenticity.

Explain the mechanism in a short defense

Use claim, evidence, limitation and an invalidating change.

Worked reasoning: Name the fixture, show the trace, recompute a value and identify what the evidence does not establish.

Why is memorizing a score insufficient?

It does not demonstrate the split, procedure, source or reasoning that gives the score meaning.

Budget the five-minute demonstration

Make every segment point to a real artifact.

Worked reasoning: Show one exact input, one executed success, one expected rejection, then how a peer can replay it.

Must every student submit a new video this week?

No. This is in-class rehearsal only; the separately announced stock-prediction HW retains its own five-minute video requirement.

Written and oral assessment remain separate

The project evidence supports explanation but does not replace either examination.

Worked reasoning: What breaks if a threshold changes units, a tool gains side effects or a retrieved source loses a qualifier?

Should the course publish live exam answers here?

No. These are public study prompts and worked practice, not confidential examination papers or new grading rules.

Peer handover is an adversarial usability test

A partner locates inputs, expected behavior and one known failure without coaching.

Worked reasoning: Capture what the partner could and could not reconstruct. Incomplete handover remains a documented limitation.

Can a partner's successful replay establish generalization?

No. It supports portability within the checked environment, not external predictive or security validity.

Summary: preserve the observed state

Keep passed, failed and untested items distinct in the final result card.

Worked reasoning: Save source, inputs, manifest, replay result and draft/completed response record.

What must not be upgraded into completion?

A prepared ZIP, launched job or connected runtime without successful execution and inspected outputs.

Final integration studio and explain-back

Finish a rerunnable bounded project record

This lab integrates existing evidence rather than adding untested autonomy.

Worked reasoning: Restore 5 min; package and replay 20 min; integrity challenge 15 min; peer defense and export 20 min.

What counts as an honest stopping point?

A draft with explicit missing evidence and next action, not fabricated success or copied metrics.

Task 1: locate every hidden dependency

List expected payloads and identify any notebook-only variable.

Worked reasoning: Use a fresh working directory; the runner should use explicit paths rather than assume the notebook location.

What if it only runs beside the notebook?

The portability claim is too broad. Fix the path contract or state the required working directory explicitly.

Task 2: check case identity and ordering

Reorder a copied output and detect sequence mismatch before numeric comparison.

Worked reasoning: A length match alone does not establish observation identity.

When is an explicit ID join acceptable?

When IDs are unique and required membership is checked, and the alignment rule is recorded in the evidence.

Task 3: state the actual environment

Read the generated version record rather than an assumed Colab configuration.

Worked reasoning: A Colab link is a launch route, not proof that the notebook was run in a Google Colab browser.

Why does this distinction matter?

Dependency, network and runtime behavior can differ. Execution claims should name the environment actually tested.

Task 4: inspect the extracted package

Check file whitelist, manifest completeness and payload hashes.

Worked reasoning: Do not replace an absent file with a freshly invented one and call the same bundle complete.

What does an intact archive prove?

Its stored bytes can be read without CRC errors; it does not prove scientific correctness or code safety.

Task 5: require actual process completion

Check return code and parsed output after the new interpreter exits.

Worked reasoning: A failed or timed-out process remains an observed failure with its diagnostic output.

What is the acceptance condition?

Successful termination, required result schema and the declared per-case agreement checks.

Task 6: explain computational agreement

Compare saved and replayed means by case ID under fixed tolerance.

Worked reasoning: If nonzero but within tolerance, report that fact rather than replacing it with zero.

What does zero difference leave untested?

Physical data validity, external populations, real LLM behavior and unseen adversarial inputs.

Task 7: detect copied-file tampering

Modify a temporary payload and preserve the original reference.

Worked reasoning: A mismatch must prevent analysis from proceeding under the reference claim.

Can a matching digest replace peer source review?

No. Integrity and trust are distinct; a harmful file can have a perfectly matching digest.

Task 8: defend claim and limitation

A partner asks one unexpected question about mechanism or scope.

Worked reasoning: What if the readings are correlated or the protocol changes? Separate computational validity from a changed scientific task.

What is a strong answer?

One grounded in an actual artifact and explicit assumptions, with no invented deployment or accuracy claims.

Summary: prepare, do not replace, the final exam

Optional A tests metadata-only changes; optional B expands a handover checklist.

Worked reasoning: State passed, failed, untested and next action. Week 18 remains the written and oral final examination.

What should continue after this course?

The habit of defining the task, preserving data, checking execution, explaining results and bounding every claim.
