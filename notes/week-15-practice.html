Specify an engineering evidence workflow

Build a report, not a physical controller

The system summarizes synthetic readings and requests review; it never controls equipment.

Worked reasoning: Measurement meaning; unit conversion; repeated readings; uncertainty; threshold; source provenance.

What does 'review required' mean here?

A fictional class protocol requests human review. It is not a hardware safety diagnosis or a command to act.

A row needs physical meaning

Our readings are repeated temperature observations of one synthetic bench case.

Worked reasoning: Five repeated readings belong to one fictional case, not five independent deployment trials.

Why does row meaning affect evaluation?

It determines the unit of analysis and whether a reported sample size counts cases, readings or correlated repeats.

Units are part of the input type

Accept C or F explicitly; convert before comparing a Celsius threshold.

Worked reasoning: 176 F becomes (176-32)*5/9 = 80 C. Mean 176 F is not compared directly with 80 C.

What should happen to an unknown unit?

Reject it with a specific error. Never infer units from a plausible numeric range.

Summaries answer different questions

Mean describes location; sample standard deviation describes observed spread.

Worked reasoning: [78,80,82] C has mean 80 C and sample SD 2 C, using denominator n-1.

Is sample SD an uncertainty guarantee?

No. It summarizes observed spread; calibration, dependence, drift and measurement uncertainty require additional evidence.

Missing and nonfinite data require a policy

Reject missing, Boolean, infinite and NaN readings in this reference.

Worked reasoning: A missing reading does not become zero, and dropping it changes the sample definition.

Why require at least two readings?

The sample SD with denominator n-1 is undefined for one observation. A different contract could return an explicit unavailable spread.

The threshold comes from a source

A versioned fictional teaching protocol sets review if mean >=80 C.

Worked reasoning: Mean exactly 80 C must request review under the declared inclusive rule.

Is this a certified safety limit?

No. It is a transparent original teaching fixture with no real equipment authority.

Predeclare behavior for disagreement

If required source evidence is absent, abstain rather than invent a threshold.

Worked reasoning: Mean 81 C without the source threshold does not justify a protocol-based review status.

Can a model fill the missing protocol from memory?

Not under this evidence contract. Ask for the approved source snapshot.

Separate data errors from review decisions

A valid high mean can yield review; invalid readings yield rejection.

Worked reasoning: Valid low mean, valid equality mean and missing unit must have different statuses.

Why is this distinction important?

A data-quality failure cannot be presented as a successful numerical or engineering conclusion.

Make the report schema explicit

Return case ID, input hash, mean C, sample SD C, source and status.

Worked reasoning: Locate the exact source ID and input digest before reading the prose summary.

Which field proves measurement authenticity?

None. A digest preserves byte identity relative to a reference, not instrument authenticity or physical validity.

Summary: define meaning before automation

Units, sample definition, protocol and forbidden actions precede code generation.

Worked reasoning: Explain why a single reading is rejected and why equality triggers review.

What does the next hour implement?

A deterministic workflow and trace. An optional LLM can propose structured inputs but cannot bypass its checks.

Implement a checked analysis pipeline

The workflow is a graph with gates

Each stage has explicit inputs, outputs and failure behavior.

Worked reasoning: The reference uses a known graph so students can inspect each transformation without a framework.

Why keep the first implementation deterministic?

It is a clear baseline for arithmetic, units and source rules before adding uncertain language-model decisions.

Validate the complete request

Require exact fields and a case ID before reading numeric values.

Worked reasoning: A request containing execute_shell is invalid even if its readings are numeric.

Why reject unexpected fields?

It avoids silently accepting ambiguous capabilities. Unknown metadata must be added by an explicit contract revision.

Conversion needs fixture tests

Test both identity in C and a known F conversion.

Worked reasoning: [78,80,82] C and [172.4,176,179.6] F should produce the same summary within declared tolerance.

Why use numeric tolerance?

Floating-point conversion can introduce small rounding differences. Equality of decisions at the threshold also needs a stated numeric policy.

Preserve the threshold comparison policy

Compare converted means after rounding to 10 decimal places in this teaching workflow.

Worked reasoning: A mathematically equal Fahrenheit fixture should not fall below the threshold due only to binary rounding.

Is this a universal measurement policy?

No. It is a declared computational convention. Real tolerances should follow measurement resolution and application requirements.

The sample SD has a declared denominator

Use ddof=1 and reject n<2 before computing spread.

Worked reasoning: For [78,80,82], squared deviations sum to 8; divide by 2, then sqrt gives 2.

Would dividing by n be equally valid here?

It answers a different statistic. The contract explicitly requests sample SD, so a population-SD implementation is a mismatch.

Trace stage outputs without excessive data

Record stage, status, digest and bounded evidence.

Worked reasoning: Find validate, convert, summarize, protocol and report in order; a failure must not create later successful stages.

Can trace order expose a hidden shortcut?

It can reveal an inconsistency, but trustworthy execution also needs source inspection and independent expected outputs.

Abstention is a valid terminal result

Missing source returns no protocol-based review conclusion.

Worked reasoning: Keep valid readings but call with no approved source. The result must not claim review status.

Why not use a default threshold?

A default would silently invent authority absent from the declared input evidence.

A report must distinguish facts and limits

Numerical summary, protocol comparison and limitation belong in separate fields.

Worked reasoning: Synthetic case A has mean 80 C; fictional protocol P1 requests review at or above 80 C; no physical diagnosis follows.

What is an unsupported extension?

Claiming overheating, failure probability or a safe operating condition without relevant physical validation.

Test an AI-generated patch as new code

Review data flow and fixtures before replacing the reference.

Worked reasoning: The patch uses sum(values)/(n+1). Predict why a zero-mean fixture can conceal it.

Why not trust plausible prose explaining the patch?

Only source, independent expected values and execution outcomes establish its behavior on tested cases.

Summary: preserve the reference workflow

Save checked inputs, configuration, source, trace and result before extension.

Worked reasoning: Download the ZIP and identify one failure case. Do not overwrite the original with an experimental change.

What does H3 complete?

The eight-task evidence record, peer explanation and one optional extension while keeping the reference reproducible.

Studio I: build, probe, and explain

Deliver one complete analysis chain

A partner must follow input, conversion, source and conclusion.

Worked reasoning: Restore 5 min; fixtures 20 min; controlled change 15 min; peer handover and export 20 min.

What is the minimum useful handover?

Runnable source plus inputs, expected fixtures, actual trace, result and an honest limitation.

Task 1: classify the contract outcomes

Predict low, equality, high and malformed cases before execution.

Worked reasoning: Low returns reported; equal/high return review_required; malformed returns rejected.

Does reported mean physically safe?

No. It means the fictional report pipeline completed below its class threshold. No real safety claim is authorized.

Task 2: audit provenance fields

Find case ID, request hash, protocol ID and implementation version.

Worked reasoning: A case ID names a record; a hash identifies canonical JSON bytes; a source ID locates the protocol.

Can any one identifier replace the others?

No. They answer different questions and each has a limited scope of uniqueness or trust.

Task 3: prove unit equivalence

Compare equivalent C and F requests with the same underlying values.

Worked reasoning: Use explicit tolerance for mean and SD, then compare the declared rounded decision value.

What if raw values match but units differ?

They represent different temperatures. Numeric equality without units is not physical equivalence.

Task 4: explain one spread calculation

Show the intermediate squared deviations and denominator.

Worked reasoning: [78,80,82] gives deviations [-2,0,2], squares [4,0,4] and SD 2 C.

What does the result not quantify?

Systematic sensor bias, calibration uncertainty or independence of repeated observations.

Task 5: locate a stopped stage

Inject an invalid unit and find where the trace ends.

Worked reasoning: The failure trace must not include a completed summary or protocol decision.

Why inspect downstream absence?

A superficial error status can coexist with partial side effects if stage ordering is wrong.

Task 6: remove source authority

Run a valid request without the approved fictional protocol.

Worked reasoning: The numerical mean can still be known while the protocol-based status is unavailable.

Is this the same as malformed input?

No. Separate numerical input validity from absence of evidence required for the requested conclusion.

Task 7: diagnose the denominator patch

Use a nonzero-mean fixture to expose sum/(n+1).

Worked reasoning: [79,80,81] has true mean 80; dividing by four gives 60 and misses the inclusive review condition.

Why is this more informative than [0,0,0]?

A zero numerator yields zero under both denominators, hiding the defect.

Task 8: package and hand over

Export reference results, traces and response fields without invented answers.

Worked reasoning: The reviewer recomputes a mean and checks the source threshold and review rule.

What should happen if a field is blank?

Keep draft status. Nonempty explanations establish completeness only, not correctness.

Summary: expand scope only with new tests

Optional A adds K conversion; optional B checks reading-order invariance.

Worked reasoning: Identify a computed number, a source-derived rule and an unverified physical assumption.

What connects to Studio II?

Evaluate competing implementations on a frozen case set, including both ordinary functionality and required rejections.
