Two roles, one individual submission

Author: send your reviewed HW9 package to a classmate and record the feedback on your own package. Each student submits their own notebook, receipt and explanation; this is not a shared grade. Use a course alias instead of private contact details.

Work through the starter in this order

  1. Inspect the handover. Check that the HW9 package is completed and contains README, requirements, source, exact data and contract, frozen plan, reference predictions and manifest. Read the submitted Python before running it. This is ordinary reviewed course Python, not a sandbox for hostile code.
  2. Use a clean receiver session. Upload the received ZIP via the Colab Files sidebar. The starter checks file integrity, extracts into a new directory and launches a new Python process. Do not mount Drive or provide credentials. In Jupyter, place the ZIP next to your notebook.
  3. Compare by ID. Refit using train only and the already frozen selection. Compare all 120 test predictions for both baseline and candidate, aligned by run_id. The declared tolerance is atol=1e-8, rtol=1e-10. A matching rounded MAE alone does not establish successful replay.
  4. Keep failures and repairs. Inspect sender/receiver versions and the first error. Retain each attempt in replay history with package identity. Correct the actual contract/source/environment when justified, and rerun. Request a corrected package from the author when the author’s artifact is wrong. Do not edit reference predictions or widen tolerance to force a pass.
  5. Implement one negative test. Change exactly one item in a copied input contract—for example, one declared unit or a missing required unit. Keep original data and contract unchanged. Show that the input loader rejects it with the expected clear message before fitting; explain the rejecting check. An arbitrary crash or unchanged test function does not establish a successful rejection test.
  6. Label the result and export. Record whether the received package came from a real other person. Describe receiver actions and feedback on your own package. Complete your one-page explanation and AI disclosure, then inspect and download the receiver evidence ZIP. Save the edited notebook separately.

The shared case: equipment temperature rise

The fixed CSV contains 600 independent synthetic equipment experiments, with a supplied 360/120/120 train/validation/test split. The rows are constructed for teaching; they are not measurements or validation of a real thermal system.

Column Meaning Unit and rule
run_id Stable experiment identity Unique string; not an ML feature
power_W Applied power W
airflow_m_s Airflow condition m/s
ambient_C Ambient condition °C
temp_rise_C Target: temperature rise above ambient °C difference; not absolute device temperature
split Frozen membership train, validation, or test; not an ML feature

The declared bounds check input encoding; they are not equipment safety limits. The contract records units, split counts and a digest of ID-keyed records. Random splitting is justified by this constructed independent-row assumption. It does not justify random splitting of a real time series. Scaling fits train only; validation selects; test provides a predeclared diagnosis after the proposal is frozen.
