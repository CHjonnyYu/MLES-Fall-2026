Digital twin foundations and credibility

Separate a geometry model, a one-off simulation, and an evidence-updated digital twin; design a credibility card for a package decision.

How this week works: Three approximately 56-minute modules plus two short transitions. Each hour has a distinct teaching target and a reviewable evidence checkpoint. InPack.AI is the course analysis platform; the handout records assumptions and outputs without inventing a software feature.

Public case: NIST digital-twin credibility framework

NIST discusses how model credibility depends on the intended use, verification, validation, and uncertainty evidence. Apply that framework to a public package warpage case without asserting that the case is an InPack.AI validation.

Evidence boundary: A framework explains what evidence is needed; it does not supply validation data for the classroom model.

Teaching modules

H1 · What makes a packaging model a twin?

Outcome: Identify the physical asset, model, data link, and decision served by a digital twin.

Evidence to keep: A four-part twin map with a named physical specimen and update rule.

Open H1 slidesSource notes

A simulation is a bounded calculation

A model predicts a quantity for specified geometry, materials, loads, and boundary conditions; one run does not by itself create a twin.

Worked reasoning: A finite-element warpage run at 25 °C is useful, but without a physical specimen, observed data, and an update rule it remains a simulation.

Check your understanding: Is a detailed 3D model automatically a twin?

No. Fidelity alone does not establish a data-connected, intended-use twin.

Sources: R5 R6

Identify the physical counterpart

The twin must refer to a defined package, lot, tool, or process state, not an unspecified generic package.

Worked reasoning: For a fan-out wafer case, record wafer size, die arrangement, material batch, and whether the observation is after debond or after grinding.

Check your understanding: Can a measurement from another process stage update this state directly?

Only after the stage difference is accounted for; otherwise the records are not comparable.

Sources: R5 R8

Data updates need a rule

A data connection must state what is measured, when it arrives, how it is checked, and which model parameter or state it changes.

Worked reasoning: A measured warpage value arrives. Check units and temperature, then revise a specified boundary or state estimate; keep the prior model version.

Check your understanding: Is uploading a file enough to claim synchronization?

No. The update mapping and validation checks must be explicit and reproducible.

Sources: R5 R6

The twin serves a decision

The intended use determines required accuracy, update frequency, and consequences of a wrong prediction.

Worked reasoning: A screen for gross wafer handling risk may tolerate different error than a final fine-pitch alignment decision; state the decision before choosing a model.

Check your understanding: Can one accuracy statement cover every use?

No. Credibility is conditional on the quantity, range, and decision stakes.

Sources: R5 R6

H2 · Verification, validation, and uncertainty

Outcome: Distinguish code correctness, physical agreement, calibration, and residual uncertainty.

Evidence to keep: A validation plan naming reference measurements, split cases, error metric, and acceptance rule.

Open H2 slidesSource notes

Verification checks implementation

Verification asks whether equations and numerical methods were implemented as intended; it is separate from physical agreement.

Worked reasoning: Refine a mesh or compare a simple analytic benchmark. Even a converged result can be physically wrong if material data are wrong.

Check your understanding: Does mesh convergence prove package accuracy?

No. It addresses a numerical question, not the match to physical observations.

Sources: R6

Validation compares with reality

Validation asks how well predictions match measurements for an intended use and tested conditions.

Worked reasoning: The published fan-out study compares simulation with measured warpage across process stages and notes a thin-wafer discrepancy; report both agreement and failure region.

Check your understanding: Can an average error hide a critical failure region?

Yes. Examine stage, thickness, geometry, and residual pattern.

Sources: R6 R8

Calibration is not independent validation

A parameter fitted to one set of measurements must be assessed on independent conditions before broader claims.

Worked reasoning: Fit a stress-free temperature using one coupon, then test a different package or temperature range; preserve the fitted value and data partition.

Check your understanding: Is fit error on the calibration data a validation metric?

No. It is training or calibration fit; independent checks are needed.

Sources: R6

Uncertainty has several sources

Material properties, geometry, process history, measurements, and model form each can change a prediction.

Worked reasoning: For warpage, list CTE uncertainty, cure-state history, thickness tolerance, fixture influence, and optical measurement uncertainty.

Check your understanding: Should one confidence interval be used without a source model?

No. State how each uncertainty was estimated and propagated.

Sources: R6 R8

H3 · Build the credibility card

Outcome: Write an intended-use claim with evidence and explicit limits for an InPack.AI course case.

Evidence to keep: A credibility card with versioned inputs, reference data, residuals, and a next validation test.

Open H3 slidesSource notes

Write intended use first

A credibility card begins with a narrow question such as ranking two candidate layouts at one process stage.

Worked reasoning: State 'compare post-reflow warpage at 25 °C' rather than 'predict package reliability'; name the package and output definition.

Check your understanding: Why is 'accurate digital twin' too broad?

It lacks a quantity, condition, tolerance, and intended decision.

Sources: R6

Trace each number

Every model output and reference measurement needs a case ID, units, temperature, stage, location, and version.

Worked reasoning: If the classroom export omits a boundary condition, mark it missing; do not fill it from the public warpage paper.

Check your understanding: May the published paper supply our missing case input?

Only if it is explicitly the same case and justified; otherwise no.

Sources: R6 R8

Inspect residuals, not one score

The pattern of prediction minus measurement across cases can reveal a missing mechanism or measurement bias.

Worked reasoning: A synthetic teaching table has residuals +12, +4, -2 µm. Check stage and temperature before summarizing; do not call this InPack.AI evidence.

Boundary: The residuals are synthetic classroom numbers.

Check your understanding: Could a low mean residual hide large individual errors?

Yes. Signed errors can cancel, so inspect each case and absolute error.

Sources: R6

State the next falsifiable check

A good next test is small enough to run and specific enough to change the decision if it fails.

Worked reasoning: If ranking depends on EMC CTE, test coupons or measure warpage at two temperatures bracketing the expected transition.

Check your understanding: When should the recommendation be withheld?

When the uncertainty or missing validation can reverse the decision under the intended use.

Sources: R6 R8
